# Contributor instructions

Keep one implementation writer and use an independent read-only review for substantial changes.
Never commit credentials, customer originals, recordings, transcripts, private configurations or runtime databases.
Use synthetic fixtures and isolated state for tests. Preserve evidence, historical conclusions and explicit identity associations.
Do not call an archive or collection success an analysis success. Do not send external messages or write CRM during tests.
Run npm test, Python unittest and npm run build. Desktop is the current scope.
